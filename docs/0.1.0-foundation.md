# 0.1.0 Foundation

## Goal

Establish the real project structure and the first usable navigation point for eL Pack Manager.

This version is a development foundation, not a player-testing release.

## What 0.1.0 should establish

### Project structure

- Shared/common code
- Fabric implementation
- NeoForge implementation
- Shared version information
- Loader-specific entry points
- Basic client initialization

### Main menu

Add an **eL Pack Manager** button to the Minecraft title screen.

The button opens the Pack Manager screen.

### Pack Manager screen

The first screen establishes the navigation used by later versions.

Planned sections:

- Resource Packs
- Data Packs
- Profiles
- Library
- Resource Pack Editor

In 0.1.0, sections that are not implemented yet may be visibly disabled rather than pretending to work.

### Common data model

Begin with simple shared types for:

- pack identity
- pack source
- pack kind
- profile identity

Do not build the full pack-management system yet.

## Rules for 0.1.0

1. Do not modify installed packs.
2. Do not modify world data.
3. Do not add dependencies that are not required.
4. Do not create a giant abstraction layer before it is needed.
5. Keep Fabric and NeoForge client hooks thin.
6. Keep the code easy to follow.
7. A successful build is the minimum automated gate for this version.
8. Player/manual testing begins with 1.0.0, not with 0.1.0.
